# Automated Quality Gates for AI-Assisted & Human Code

Because AI coding assistants can produce plausible-looking code that harbors subtle concurrency bugs, integer overflows, or missing error checks, AegisCam enforces **8 automated CI gates** (`.github/workflows/ci.yml`) on every pull request regardless of whether code was written by a human or an AI assistant.

---

## 1. The 8 CI Quality Gates (Spec §7)

| Gate | CI Job | Tooling | What It Catches (Especially in AI-Generated Code) |
|------|--------|---------|---------------------------------------------------|
| **Gate 1** | `format-and-lint` | `clang-format --dry-run -Werror`, `clang-tidy`, `gofmt -l`, `go vet` | Style drift, uninitialized members, implicit narrowing conversions, forgotten `override`, suspicious Go constructs. |
| **Gate 2** | `cpp-build-and-test` & `cross-aarch64` | GCC + Clang (`Debug`/`Release`) + `aarch64-linux-gnu-g++` | Compiler-specific extensions, signedness assumptions (`char` is unsigned on ARM64!), missing headers. |
| **Gate 3** | `cpp-build-and-test` & `go-test` | `ctest --output-on-failure`, `go test -race ./...` | Functional regressions and concurrent map/slice data races in Go `netagent`. |
| **Gate 4** | `sanitizers` | Clang `asan-ubsan` + `tsan` CMake presets | Heap buffer overflows, use-after-free, signed integer overflow, memory leaks, and C++ data races. |
| **Gate 5** | `coverage` | `gcovr --fail-under-line 80` on `crypto`, `evidence`, `recording`, `ota` | Untested error branches or dead code generated by an LLM. |
| **Gate 6** | `fuzz-smoke` | `libFuzzer` (`fuzz_command_protocol`, 60 s run) | Out-of-bounds reads, `std::stoi` exceptions, or infinite loops on malformed IPC input. |
| **Gate 7** | `system-tests` | `pytest tests/system` + `tools/verify_evidence.py` | End-to-end contract mismatches between C++ `aegisd --sim` and the offline cryptographic verifier. |
| **Gate 8** | `ai-governance-gate` | PR template + `ai-assisted` label check | Undisclosed AI-assisted changes bypassing the 2-reviewer human approval requirement. |

---

## 2. Why Deterministic Verification Beats Subjective Review

LLMs are fluent in syntax but do not execute code. By pairing:
- **Static analysis** (`clang-tidy`, `go vet`),
- **Dynamic sanitizers** (`ASan`, `UBSan`, `TSan`, `go test -race`),
- **Property/fuzz testing** (`libFuzzer`), and
- **Independent cross-language verification** (C++ `EvidenceStore` verified by Python `tools/verify_evidence.py`),

any bug introduced by an AI assistant in hash chaining, buffer indexing, or protocol parsing fails deterministically in CI before merge.
